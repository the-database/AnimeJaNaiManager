# Addon Manager review notes

This is the Manager companion to the API 1.12 host/player PR set. The complete reviewer entry point and creator manual are `addons/REVIEW-GUIDE.md` and `addons/DEVELOPER-GUIDE.md` in `mpv-AnimeJaNai`. [ADDONS.md](ADDONS.md) documents local fixture and real-host testing.

The Addons tab is visible only on Windows installations with the host/runtime files. It connects automatically when addons are installed; merely opening an empty tab starts no host. Choosing to install a package starts the host for that explicit action. Users install `.ajnaddon` files, review requested permissions, configure typed fields, run declared actions, start/stop addons and restore a previous package. It does not expose a host address, arbitrary guest UI code, shell execution or native DLL installation.

Review `Views/AddonsView.axaml*` for basic state/selection handling and the partial files for media, network, listener, Windows-login, performance-limit and help flows. File/profile/destination approvals are tied to the reviewed package; cancellation and revocation are explicit. Unsaved settings survive unrelated operations and require confirmation before discard. MainWindow retains the 3.9.0 saved UI state and diagnostics shutdown behavior alongside addon lifecycle cleanup.

`Services/AddonHostClient.cs` is an exact normalized copy of the main repo's canonical management client. `addon-sdk-source.json` records its source and checksum; that commit is currently available through upstream PR 227, not merged main. `tools/check-addon-client.ps1` checks the in-tree copy without downloading from a contributor fork. An optional canonical path also checks the host checkout. During coordinated review the UI CI workflow pins a full immutable PR commit. Merge host PR 227 first, then replace the workflow pin with its resulting commit on `main` and run the UI workflow before merging Manager PR 20. Use the resulting main commit even for a squash or rebase merge; do not rely on the old PR commit remaining reachable. Release builds need no remote host checkout.

Tests: configuration/Temporal Fix round trips, Diagnostics, AddonUi fixture tests and the optional real packaged-host path described in ADDONS.md. The 3.9.0 port passed these relevant fixture/configuration checks; the host/player qualification is recorded separately in the main review document. The headless test uses Avalonia 12.1.4 and drains dialog continuations before issuing the next close action.

An unused Addons tab does not start an empty host merely to poll it. Manager rechecks support files when its window regains focus, so installing support while it is open reveals the tab without restarting Manager. This adds no timer or player work. Enabled addons can have their own activation rules and work. Manager supplies controls and reviewed access; it does not implement Plex or lighting logic. There is no community catalog or publisher-signature UI in this preview.

Manager checks that the host/runtime exists before acquiring its activity lock or waiting for a connection. Actual window closure cancels startup; a close veto from diagnostics or unsaved settings leaves the Addons tab usable. Host diagnostics go to the host's own `diagnostics/host.log`, not pipes owned by Manager. Destination consent warns about plaintext credentials and access to loopback/link-local services.

`tests/AddonUi` runs its normal fixture checks, including a later close veto, by default. The `AJN_UI_CASE=startup-close`, `missing-runtime` and `empty-installation` cases run in separate processes so static application paths cannot leak between fixtures. These tests cover cancellation, hidden unsupported UI and avoiding empty-host startup; they do not establish native player behavior.
